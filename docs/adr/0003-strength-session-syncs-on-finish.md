# An in-progress strength session is kept on the device and saved on finish

Logging each set with its own request made the session screen wait on the network for every tick, and it felt slow in a gym with a weak signal. While a session is in progress, ticks, edits and added or removed sets now change the page at once and are kept in the browser's local storage, so a reload or leaving the app loses nothing on that device. Finishing sends the whole session in one request, which replaces the stored sets for its exercises before the session is marked finished. The trade-off: until it is finished, the sets exist only on the phone they were logged on, so another device (or the MCP) sees the session with no sets. Swapping, skipping and adding exercises still go to the server, which owns the exercise library, and a finished session's corrections still save straight away.
